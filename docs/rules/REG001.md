# REG001 — Tool-registry schema names a parameter absent from the signature

**Namespace:** `REG`  
**Severity:** 🔴 error  
**Fix:** No automatic fix

---

## Description

DOC007's phantom-parameter case, lifted from the docstring `Args:` section to a
programmatic tool schema. Fires when a `parameters.properties` key in a
**same-file** tool-registry entry — a `ToolDefinition(...)` constructor or a
`{"name": ..., "parameters": {...}}` dict literal — names a parameter the
registered function's signature does not have. The entry is recognized in any of
the module-level positions docpact extracts (a list element, an assignment value,
a bare expression, or a direct argument to a registration call such as
`register_tool(ToolSpec(...))`; see ADR-011). The usual cause is a rename applied
to the signature (and docstring) but missed in the schema, leaving an LLM caller
describing a parameter that no longer exists.

This is a *consistency* check, not a *completeness* one: like DOC007's phantom
sub-case it fires at all tiers. It is **same-file only** (ADR-005) — the entry's
`name` must match a function defined in the same module. An entry whose `parameters`
is not a static dict literal (`property_keys` cannot be enumerated) is skipped, the
same literals-only discipline DOC021 applies to default values.

`REG` is opt-in: add it to `select`. (For the *cross-file* version — an entry whose
handler is imported from another module — see REG011.)

## Examples

### Triggering — schema names a parameter the function lacks

```python
def search_cases(query: str, limit: int) -> list:
    """Search cases."""
    ...


BOT_TOOLS = [
    ToolDefinition(
        name="search_cases",
        parameters={
            "type": "object",
            "properties": {
                "query": {"type": "string"},
                "qry": {"type": "string"},  # phantom — signature has 'query', not 'qry'
            },
        },
    ),
]
```

```
tools.py:7:4: REG001 Tool-registry schema for 'search_cases' documents parameter 'qry', which is absent from the function signature
```

### Passing — schema keys all exist in the signature

```python
BOT_TOOLS = [
    ToolDefinition(
        name="search_cases",
        parameters={"properties": {"query": {"type": "string"}, "limit": {"type": "integer"}}},
    ),
]
```

## Configuration

`REG` is opt-in:

```toml
[tool.docpact]
select = ["DOC", "REG"]
```

The registered class name(s) and field names are configurable:

```toml
[tool.docpact.registry]
tool_definition_class = ["ToolDefinition"]  # raw dict literals are always recognized
name_field = "name"
parameters_field = "parameters"
```

Disable REG001 specifically:

```toml
[tool.docpact]
ignore = ["REG001"]
```

Or suppress inline, on the registry entry's line:

```python
BOT_TOOLS = [
    ToolDefinition(name="search_cases",  # nodo: REG001 -- schema key kept for back-compat
        parameters={"properties": {"qry": {"type": "string"}}}),
]
```
