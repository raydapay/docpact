# TY001 — Returns section present but return annotation is 'None'

**Namespace:** `TY`  
**Severity:** 🔴 error  
**Fix:** No automatic fix

---

## Description

Fires when a function is explicitly annotated `-> None` but its docstring contains a Returns section with substantive content. The annotation says the function returns nothing; the section claims otherwise. One of them is wrong.

**Exclusions:**

- Functions with no return annotation are excluded. The contradiction cannot be confirmed without an explicit annotation.
- Returns sections whose body is a None-equivalent (`None.`, `None`, `N/A`, `NA`, or empty) do not fire. Those express the absence of a return value explicitly, which is structurally correct (if redundant alongside `-> None`).

TY001 is a purely annotation-based check. It does not inspect runtime behavior or call `ty`.

## Examples

### Triggering

```python
def publish_event(event: dict) -> None:
    """Publish an event to the message bus.

    Args:
        event: Event payload to publish.

    Returns:
        The message ID assigned by the broker.  # contradicts -> None
    """
```

TY001 fires: annotation is `None` but Returns section documents a value.

### Passing — annotation and section agree

```python
def publish_event(event: dict) -> str:
    """Publish an event to the message bus.

    Args:
        event: Event payload to publish.

    Returns:
        The message ID assigned by the broker.
    """
```

### Passing — canonical empty Returns with -> None (explicit, not contradictory)

```python
def flush_cache() -> None:
    """Evict all entries from the in-process cache.

    Returns:
        None.
    """
```

### Passing — unannotated (excluded)

```python
def legacy():
    """Compute something.

    Returns:
        The result.
    """
```

## Rationale

A `-> None` annotation is a contract: the caller should not use the return value. A Returns section that documents a value breaks that contract in documentation. The annotation came from the implementation; the section came from the docstring. When they disagree, one was not updated — and agents reading the docstring will call the function incorrectly.

## Configuration

Disable globally:

```toml
[tool.docpact]
ignore = ["TY001"]
```

Suppress inline (on the `def` line):

```python
def side_effect(  # nodo: TY001 -- annotation incorrect, fix tracked in #201
    x: int,
) -> None: ...
```
