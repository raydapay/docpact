# REG010 — Tool Args section out of parity with its imported input model

**Namespace:** `REG`  
**Severity:** 🟡 warning  
**Fix:** No automatic fix

---

## Description

Cross-file rule (ADR-010). A tool-registry entry that names an **imported**
Pydantic model as its `input_model` and documents parameters in its
description's `Args:` section is asserting two things that must agree: the
documented args and the model's actual fields. REG010 fires when they drift — a
model field the `Args:` omit, or a documented arg with no matching model field.

It is the cross-file counterpart of DOC007's phantom/missing-parameter check,
lifted to a model defined in another module. Resolution is delegated to a
language server (`[tool.docpact.lsp]`, default `ty`): docpact asks it to resolve
the imported model to its defining file, then extracts the fields by its own
static AST pass — it never imports or executes your code.

**Runs only under `docpact check --crossfile`** and only when `REG` is in
`select`. A model the server cannot resolve is skipped (under-enforce, never
guess); a missing or failing server degrades gracefully.

## Examples

These are cross-file: the model and the registry live in different modules.

### Triggering — a model field the docs omit

```python
# schemas.py
from pydantic import BaseModel


class SearchInput(BaseModel):
    query: str
    limit: int
```

```python
# tools.py
from schemas import SearchInput

TOOLS = [
    ToolDefinition(
        name="search",
        input_model=SearchInput,
        description=(
            "Search transactions.\n\n"
            "Args:\n"
            "    query: Full-text match against the description.\n"
            # 'limit' is a field of SearchInput but is not documented here
        ),
    ),
]
```

Run with `docpact check . --crossfile` (and `REG` selected):

```
tools.py:4:4: REG010 input model 'SearchInput' field 'limit' is not documented in tool 'search' Args section
```

The reverse direction fires too — a documented arg with no matching model field:

```
tools.py:4:4: REG010 tool 'search' Args entry 'offset' has no matching field in input model 'SearchInput'
```

### Passing — Args and model fields match

```python
# tools.py
TOOLS = [
    ToolDefinition(
        name="search",
        input_model=SearchInput,  # fields: query, limit
        description=(
            "Search transactions.\n\n"
            "Args:\n"
            "    query: Full-text match against the description.\n"
            "    limit: Maximum number of results to return.\n"
        ),
    ),
]
```

## Configuration

REG010 is opt-in twice over: enable the namespace and pass the flag.

```toml
[tool.docpact]
select = ["DOC", "REG"]   # REG010 needs the REG namespace

[tool.docpact.lsp]
server = ["ty", "server"]  # swappable: ["pyright-langserver", "--stdio"], …
```

```bash
docpact check src/ --crossfile
```

Disable it specifically:

```toml
[tool.docpact]
ignore = ["REG010"]
```

Or suppress inline, on the registry entry's line:

```python
TOOLS = [
    ToolDefinition(name="search", input_model=SearchInput,  # nodo: REG010 -- schema is intentionally narrower
        description="..."),
]
```
