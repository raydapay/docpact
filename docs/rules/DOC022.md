# DOC022 — Typed prose annotation doesn't match signature type

**Namespace:** `DOC`  
**Severity:** 🟡 warning  
**Fix:** No automatic fix

---

## Description

Fires **only** when an `Args` entry contains an explicit inline type annotation —
the `name(type): description` form — and that type doesn't match the parameter's
annotation in the signature. Entries without an inline type (`name: description`)
are ignored entirely.

The rule verifies explicit claims. If you wrote a type in prose, you made a claim;
DOC022 checks it is consistent with the signature.

### Known false positives — notation differences

Type comparison is string-based after whitespace stripping. No semantic equivalence
is attempted. The following pairs produce a DOC022 warning even though the types
are semantically identical:

| Prose (docstring) | Signature | Verdict |
|---|---|---|
| `Optional[str]` | `str \| None` | fires — pre/post PEP 604 |
| `List[int]` | `list[int]` | fires — pre/post PEP 585 |
| `Union[A, B]` | `A \| B` | fires — pre/post PEP 604 |
| `"Foo"` | `Foo` | fires — stringified vs bare reference |

**Pre-PEP 604 codebases** (`Optional[...]`, `Union[...]` style) will see noise from
DOC022 if they also write inline types in docstrings. The recommended fix is to
either drop inline types from docstrings (the common modern style, which DOC022
ignores entirely) or suppress with `# nodo: DOC022 -- notation style difference`.

## Examples

### Triggering

```python
def foo(x: float) -> None:
    """Summary.

    Args:
        x (int): description  # fires: prose says int, signature says float
    """
```

```python
def bar(value: str | None) -> None:
    """Summary.

    Args:
        value (Optional[str]): description  # fires: notation mismatch
    """
```

### Passing

```python
def foo(x: float) -> None:
    """Summary.

    Args:
        x: description  # no inline type — DOC022 ignores this
    """
```

```python
def bar(value: str) -> None:
    """Summary.

    Args:
        value (str): description  # types match
    """
```

## Configuration

This rule can be disabled with:

```toml
[tool.docpact]
ignore = ["DOC022"]
```

Or suppressed inline:

```python
def my_function(  # nodo: DOC022 -- reason
    ...
```
