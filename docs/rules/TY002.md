# TY002 — Returns section is 'None.' but return annotation is non-None

**Namespace:** `TY`  
**Severity:** 🟡 warning  
**Fix:** No automatic fix

---

## Description

Fires when a function has a non-None return annotation but its Returns section body is `None.` — the canonical empty form. The annotation promises a return value; the section explicitly says there is nothing to document. DOC012 is satisfied (the section exists), so this contradiction goes undetected without TY002.

**Exclusions:**

- Functions with no return annotation are excluded. DOC012 handles the missing-section case for unannotated functions at the appropriate tier.
- Returns sections with substantive body content are not flagged — that case is handled by DOC012 (if the section is missing) or is clean.

Only the exact string `None.` (after stripping whitespace) triggers TY002. Other non-canonical empty forms are handled by DOC013.

## Examples

### Triggering

```python
def get_user(user_id: str) -> dict:
    """Fetch a user record.

    Args:
        user_id: UUID of the user to fetch.

    Returns:
        None.  # contradicts -> dict
    """
```

TY002 fires: annotation is `dict` but Returns section is `None.`.

### Passing — section matches annotation

```python
def get_user(user_id: str) -> dict:
    """Fetch a user record.

    Args:
        user_id: UUID of the user to fetch.

    Returns:
        User record with id, email, created_at, and role fields.
    """
```

### Passing — -> None with None. (redundant but not contradictory)

```python
def flush() -> None:
    """Flush the output buffer.

    Returns:
        None.
    """
```

TY001 does not fire (body is None-equivalent). TY002 does not fire (annotation is None).

### Passing — unannotated function (excluded)

```python
def compute():
    """Compute a value.

    Returns:
        None.
    """
```

## Rationale

`None.` in a Returns section is a deliberate statement: "I considered the return value and there is nothing to say." When the annotation is `dict` or `str` or any other type, that statement is wrong. The section was either copy-pasted from a void function or never updated when the return type was added. TY002 catches this specific contradiction that DOC012 cannot see (the section exists) and TY001 does not cover (the annotation is non-None).

## Configuration

Disable globally:

```toml
[tool.docpact]
ignore = ["TY002"]
```

Suppress inline (on the `def` line):

```python
def internal_state(  # nodo: TY002 -- returns opaque handle, documentation deferred
    key: str,
) -> object: ...
```
