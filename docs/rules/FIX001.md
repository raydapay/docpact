# FIX001 — Bare inline suppression without specific rule codes

**Namespace:** `FIX`  
**Severity:** 🟡 warning  
**Fix:** No automatic fix

---

## Description

Fires when a suppression comment names no specific rule codes. A bare suppression silences every docpact diagnostic on that line — it is a blanket override with no indication of what was being suppressed or why.

A bare suppression looks like:

```python
def foo(  # nodo
```

A valid suppression names at least one code and includes a reason:

```python
def foo(  # nodo: DOC001 -- pre-docpact legacy, tracked in #412
```

FIX001 is a line-level rule. The diagnostic appears at the column of the `#` character.

The FIX namespace is opt-in. Add `"FIX"` to your `select` list to enable FIX001 and FIX002:

```toml
[tool.docpact]
select = ["DOC", "MCP", "FIX"]
```

## Examples

### Triggering

```python
def send_notification(  # nodo
    user_id: str,
    message: str,
) -> None:
    """Send a push notification."""
```

FIX001 fires: bare suppression suppresses all rules without saying which or why.

### Passing

```python
def send_notification(  # nodo: DOC012 -- Constraints section not yet written, #504
    user_id: str,
    message: str,
) -> None:
    """Send a push notification."""
```

## Rationale

A bare `# nodo` leaves reviewers with no way to tell which rule was being suppressed, whether it still applies, or whether the suppression is still needed. Named suppressions with reasons are a paper trail: they document the intent at the time, link to the follow-up issue, and make it obvious when a suppression can be removed.

## Configuration

Disable globally:

```toml
[tool.docpact]
ignore = ["FIX001"]
```

FIX001 cannot be suppressed inline — suppressing it with `# nodo: FIX001` would itself be a suppression that requires a reason (triggering FIX002). Use `ignore` or `per-file-ignores` instead.
