# DOC002 — Missing module-level docstring

**Namespace:** `DOC`  
**Severity:** 🟡 warning  
**Fix:** No automatic fix

---

## Description

Fires when a Python source file has no module-level docstring. A module docstring is the first statement of the file when that statement is a string literal.

**Exclusions:**

- `__init__.py` files are always skipped. They frequently serve as pure namespace packages or re-export surfaces where a module docstring adds little value.
- Empty files (no statements) are skipped.
- Files that fail to parse are silently skipped.

DOC002 is a file-level rule. The diagnostic appears at line 1, column 0 — the top of the file.

## Examples

### Triggering

```python
# payments.py — no module docstring at the top
from __future__ import annotations

from decimal import Decimal


def charge(amount: Decimal) -> str: ...
```

### Passing

```python
"""Payment processing utilities for the settlements pipeline."""

from __future__ import annotations

from decimal import Decimal


def charge(amount: Decimal) -> str: ...
```

## Rationale

For agent-facing code, the module docstring is the first thing a reader or tool sees. It should describe the module's purpose and scope in one or two sentences — enough to decide whether to look further. Without it, the only signal is the filename.

## Configuration

Disable globally:

```toml
[tool.docpact]
ignore = ["DOC002"]
```

Disable for generated or boilerplate files:

```toml
[tool.docpact.per-file-ignores]
"src/generated/**/*.py" = ["DOC002"]
"migrations/*.py" = ["DOC002"]
```

DOC002 cannot be suppressed inline because it is a file-level rule with no associated function. Use `per-file-ignores` for selective suppression.
