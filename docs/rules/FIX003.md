# FIX003 — Suppression comment names a code with no active violation on this line

**Namespace:** `FIX`  
**Severity:** 🟡 warning  
**Fix:** No automatic fix

---

## Description

A `# nodo: CODE -- reason` suppression is load-bearing only while the code it
names actually fires on that line. FIX003 is the mechanical complement to the
`--add-suppression` baselining workflow: once docstrings get written and
violations fixed, the `# nodo: CODE -- baseline` comments added during baselining
are never removed automatically. They accumulate as dead weight and obscure which
suppressions still matter. FIX003 fires whenever a suppression names a code that
has **no active violation on its line**.

This is a file-level post-pass rule. It runs after every other rule has been
evaluated for the file, so it can compare the full suppression map against the
complete set of violations produced for that file. For a multi-code comment
(`# nodo: DOC007, DOC012 -- reason`), it fires per stale code, not per comment.

Bare suppressions (`# nodo` with no codes) are excluded — [FIX001](FIX001.md)
owns those.

No auto-fix. Pruning one stale code from a multi-code comment versus deleting the
whole comment is a non-trivial edit; the determination is unambiguous but the
resolution is left to the author. A safe fix may be added in a future release.

## Examples

### Triggering

The `DOC012` violation has been resolved, but the baseline suppression remains:

```python
def process(  # nodo: DOC012 -- baseline
    user_id: str,
) -> dict:
    """Apply pending transforms.

    Args:
        user_id: UUID of the user record.

    Returns:
        Snapshot of the account state after all transforms applied.
    """
```

```
mod.py:1:14: FIX003 Suppression of 'DOC012' is unused — no active violation on this line
```

### Passing

The suppression names a code that is still firing on that line, so it is
load-bearing and FIX003 stays silent:

```python
def process(user_id, flags):  # nodo: DOC012 -- legacy helper, untyped on purpose
    """Apply pending transforms."""
```

## Configuration

This rule can be disabled with:

```toml
[tool.docpact]
ignore = ["FIX003"]
```

Or suppressed inline (on the `def` keyword line — see [FIX004](FIX004.md)):

```python
def my_function(  # nodo: FIX003 -- reason
    ...
```
