# DOC003 — Missing docstring on a class definition

**Namespace:** `DOC`  
**Severity:** 🟡 warning  
**Fix:** No automatic fix

---

## Description

Fires when a class body does not begin with a string literal. Applies to all class definitions in the file: top-level classes, nested classes, and inner classes. Empty-bodied classes (`pass` or `...` only) are not exempt — even a one-line summary communicates intent.

DOC003 is a file-level rule, not a function-level rule. The diagnostic appears at the line of the `class` keyword.

## Examples

### Triggering

```python
class PaymentRequest:
    # No docstring — DOC003 fires
    amount_cents: int
    currency: str
    idempotency_key: str
```

### Passing

```python
class PaymentRequest:
    """Validated request object for a single payment.

    Construct via PaymentRequest.from_dict() to apply field validation.
    """

    amount_cents: int
    currency: str
    idempotency_key: str
```

### Nested class — also checked

```python
class Outer:
    """Outer container."""

    class Inner:
        # No docstring — DOC003 fires for Inner too
        pass
```

## Rationale

Classes define contracts — fields, invariants, lifecycle. Without a docstring, the reader must reconstruct the contract from the implementation. For Pydantic models and FastMCP argument schemas, the class docstring is often the primary human-facing description of the data structure.

## Configuration

Disable globally:

```toml
[tool.docpact]
ignore = ["DOC003"]
```

Disable for generated code:

```toml
[tool.docpact.per-file-ignores]
"src/generated/**/*.py" = ["DOC003"]
```

Suppress inline on the `class` keyword line:

```python
class LegacyHelper(  # nodo: DOC003 -- grandfathered, refactor tracked in #99
    Base,
):
    pass
```
