# DOC050 — Pydantic model field missing Field(description=...)

**Namespace:** `DOC`  
**Severity:** 🟡 warning  
**Fix:** No automatic fix

---

## Description

Fires when a Pydantic model field has no `Field(description=...)`. Field-level documentation belongs in the type definition, not in the caller's Args section: a Pydantic model is a standalone contract that travels independently through the codebase, and its fields should be self-documenting.

**Detection heuristic:**

- A class is treated as a Pydantic model if any base class name contains `"BaseModel"` (covers `BaseModel`, `pydantic.BaseModel`, `pydantic.v1.BaseModel`, and custom sub-bases named `*BaseModel`).
- A field is an annotated class-body variable (`x: Type`) whose name does not start with `_` and whose annotation is not `ClassVar[...]`.
- A field is documented when its default value is a `Field(...)` call with a non-empty `description=` string (or any non-constant expression as the description value, which is accepted as potentially valid).

The heuristic errs toward false negatives (misses exotic base names) rather than false positives (noisy on non-Pydantic classes).

DOC050 is a file-level rule. Diagnostics appear at the field definition line, not at the class line.

## Examples

### Triggering

```python
from pydantic import BaseModel, Field


class PaymentRequest(BaseModel):
    amount_cents: int  # DOC050 fires — no Field(description=...)
    currency: str  # DOC050 fires
    idempotency_key: str = Field(default="")  # DOC050 fires — no description=
```

### Passing

```python
from pydantic import BaseModel, Field


class PaymentRequest(BaseModel):
    """Validated payment request."""

    amount_cents: int = Field(
        description="Amount to charge in cents. Must be positive and non-zero.",
    )
    currency: str = Field(
        description="ISO 4217 currency code (e.g. 'USD', 'EUR').",
    )
    idempotency_key: str = Field(
        default="",
        description="Caller-supplied key for deduplication. Empty string disables dedup.",
    )
```

### Passing — private fields and ClassVar excluded

```python
from typing import ClassVar

from pydantic import BaseModel


class Config(BaseModel):
    _internal: str = ""  # private — excluded
    MAX_RETRIES: ClassVar[int] = 3  # ClassVar — excluded
    timeout_seconds: int  # DOC050 fires — public field, no description
```

## Rationale

FastMCP and similar frameworks expose Pydantic model fields directly as tool argument schemas. When a field has no description, the agent sees only the field name and type — the same information available from static analysis. A description in `Field(...)` is the only place to document what the field actually means, its constraints, and its valid values.

## Configuration

Disable globally:

```toml
[tool.docpact]
ignore = ["DOC050"]
```

Disable per file:

```toml
[tool.docpact.per-file-ignores]
"src/internal/models.py" = ["DOC050"]
```

DOC050 cannot be suppressed inline on individual fields (it is file-level, not function-level). Use `per-file-ignores` or disable globally.
